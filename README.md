This project provides a Docker container for
<a href="https://www.gnucash.org/">GnuCash</a>.

Access the application's graphical user interface (GUI) via a modern web
browser—no client-side installation required. Only secure access via HTTPS is
supported.

The Docker image is based on
[jlesage/docker-baseimage-gui](https://github.com/jlesage/docker-baseimage-gui).

> [!NOTE]
> This Docker container is entirely unofficial and not made by the creators of
> GnuCash.

## Features

* **Versions**: Runs GnuCash 5.14 on baseimage-gui:ubuntu-24.04-v4.11.2.
* **Web Interface**: Access the GnuCash GUI through your web browser.
* **Secure Access**: Web interface is forced to HTTPS and optionally secured by
  a login page.
  * **Local sign-in**: Simple authentication against a local user database can
    be enabled.
  * **Oauth2 Proxy**: Authentication via an SSO identity provider (Google,
    GitHub, etc.) can be enabled.
* **Multi-Arch**: Supports `linux/amd64` and `linux/arm64`.
* **Persistence**: Configuration and data are persisted to volumes.

## Usage

### Docker Compose

1. Clone this repository:
   ```bash
   git clone https://github.com/ArturKlauser/docker-gnucash.git
   cd docker-gnucash
   ```
1. Create the volume directories:
   ```bash
   mkdir config data
   ```
1. Run the container:
   ```bash
   USER_ID=$(id -u) GROUP_ID=$(id -g) docker compose up -d
   ```
1. Access the interface at [https://localhost:5800](https://localhost:5800).
   *  Note: A self-signed certificate is generated by default, causing browser
      warnings. To avoid this, install your own certificate in `/config/certs`.
      See [How to use an existing SSL certificate](#existing-ssl-cert-setup) for
      details.
1. Shut down the container:<br>
   The container is designed to run continuously. To shut it down, first quit
   GnuCash in the GUI to release the lock on the data file. Then run:
   ```bash
   USER_ID=$(id -u) GROUP_ID=$(id -g) docker down
   ```

### Docker CLI

```bash
# For DockerHub released image:
IMAGE=arturklauser/gnucash:v1.1.0

# For locally built image:
IMAGE=gnucash

docker run -d \
  --name=gnucash \
  -p 5800:5800 \
  -v $(pwd)/config:/config:rw \
  -v $(pwd)/data:/data:rw \
  -e USER_ID=$(id -u) \
  -e GROUP_ID=$(id -g) \
  "${IMAGE}"
```

## Security

* **HTTPS**: The container enforces HTTPS for the web interface. Requests to the
  HTTP port are redirected to HTTPS.
* **VNC**: The VNC port (5900) from `docker-baseimage-gui` is disabled. Access
  is only provided through the secure web interface.
* **User Authentication**: Optionally, require users to authenticate before
  accessing the application. Uses a local user database or an SSO OAuth2
  identity provider (Google, GitHub, OIDC server, etc.).

## Configuration

### Environment Variables used by Docker Compose

| Variable | Description | Default |
| :--- | :--- | :--- |
| `USER_ID` | User ID of the user running the application. | unset (required) |
| `GROUP_ID` | Group ID of the user running the application. | unset (required) |
| `TZ` | Timezone (e.g., `Europe/Rome`). | `America/Los_Angeles` |
| `CONFIG_DIR` | Host path for the application configuration directory. | `./config` |
| `DATA_DIR` | Host path for the GnuCash data files directory. | `./data` |
| `WEB_AUTHENTICATION` | Enable web authentication. Check the documentation at [jlesage/docker-baseimage-gui](https://github.com/jlesage/docker-baseimage-gui) for details. | false (optional) |
| `WEB_AUTHENTICATION_USERNAME` | Username for web authentication. | unset (optional) |
| `WEB_AUTHENTICATION_PASSWORD` | Password for web authentication. | unset (optional) |
| `OAUTH2_PROXY` | Enable OAuth2 Proxy support. Overrides WEB_AUTHENTICATION if set. See [oauth2-proxy setup instructions](#oauth2-proxy-setup) for details. | false (optional) |

### Volumes

| Volume | Description |
| :--- | :--- |
| `/data` | Stores GnuCash data files. |
| `/config` | Stores application configuration, including generated SSL certificates (in `/config/certs`). |

> [!TIP]
> <details>
> <summary>How to copy existing GnuCash data and config from host machine to container.</summary>
>
> If you want to continue working with GnuCash data that you were using on your
> host, you need to copy several files to the container volumes:
> * **data**: Each "book" (set of accounts) stores its main data (account names,
>   transactions) in a `*.gnucash` file. This is the file that you explicitly
>   "open" in the GnuCash app. Copy this file into the container's `/data`
>   directory.
>   * Alternatively, export database-backed books (sqlite/mysql/postgres) as
>     `*.gnucash` files ("File -> Save As") for import into the container.
> * **config**: While the `*.gnucash` file contains main "book" data, UI
>   settings, saved reports, etc., are stored in separate configuration files.
>   Copy these to the container's `/config` directory. Locations vary by host
>   system:
>   * Linux host:
>     * Configuration location: `$XDG_DATA_HOME/gnucash` (usually
>       `~/.local/share/gnucash`). This directory contains `books`, `checks`,
>       `translog`, and `accelerator-map`. In `books`, there is a `*.gcm` file
>       for each data file (e.g., `.../books/foobar.gnucash.gcm` corresponds to
>       `.../foobar.gnucash`). Copy the entire `$XDG_DATA_HOME/gnucash`
>       directory to `/config/xdg/data/gnucash`.
>     * More settings: `$XDG_CONFIG_HOME/dconf/user` (usually
>       `~/.config/dconf/user`). This `dconf` database file contains settings
>       like window geometries, autosave, and API keys. Copy this file to
>       `/config/xdg/config/dconf/user`.
>
>       To inspect the file, use `dconf dump /org/gnucash/` (all settings) or,
>       e.g., `dconf read /org/gnucash/GnuCash/dialogs/tip-of-the-day/show-at-startup`
>       for a specific value. Note that `dconf` is not installed in the
>       `docker-gnucash` image.
>
>   * MacOS host:
>     * Configuration location: Open "Gnucash -> About Gnucash" to see
>       `GNC_USERDATA_DIR` and `GNC_USERCONFIG_DIR` (typically
>       `~/Library/Application Support/GnuCash`). This directory contains
>       `books`, `checks`, `config`, `accelerator-map`, and `saved-reports*`.
>       Copy the entire `GNC_USERDATA_DIR` directory to
>       `/config/xdg/data/gnucash`.
>     * More settings: `~/Library/Preferences/org.gnucash.GnuCash.plist`. This
>       file is similar to the Linux `dconf` database. Direct import isn't
>       possible. View settings with `defaults read org.gnucash.GnuCash` and
>       manually apply changes in the container's "GnuCash -> Settings" menu.
> </details>

> [!TIP]
<a id="existing-ssl-cert-setup"></a>
> <details>
> <summary>How to use an existing SSL certificate (e.g., from Let's Encrypt).</summary>
>
> The container generates a self-signed certificate by default, causing browser
> warnings. To use a trusted certificate (e.g., from
> [Let's Encrypt](https://letsencrypt.org/)), place your certificate files in
> the `/config/certs` directory.
>
> The container expects:
> * `/config/certs/web-fullchain.pem`: The full chain certificate.
> * `/config/certs/web-privkey.pem`: The private key.
>
> Example: For Let's Encrypt, copy `fullchain.cer` and `mydomain.com.key` to
> these locations.
>
> 1. Stop the container.
> 2. Copy and rename your certificate files to the `certs` subdirectory of your
>    mapped config directory (e.g., `./config/certs`):
>    ```bash
>    cp /path/to/your/fullchain.cer ./config/certs/web-fullchain.pem
>    cp /path/to/your/mydomain.com.key ./config/certs/web-privkey.pem
>    ```
> 3. Start the container.
>
> **Note:** Let's Encrypt certificates require a valid domain name, not
> `localhost` or IP addresses. Access the container using the domain name
> specified in the certificate. If using a reverse proxy, install the valid
> front-end certificate on the proxy itself. Depending on configuration (e.g.,
> `proxy_ssl_verify` for nginx), the proxy may or may not validate the backend
> (container) self-signed certificate.
> </details>

> [!TIP]
<a id="oauth2-proxy-setup"></a>
> <details>
> <summary>How to secure access with oauth2-proxy.</summary>
>
> Secure GnuCash with [OAuth2 Proxy](https://oauth2-proxy.github.io/oauth2-proxy/)
> to authenticate users via external providers (Google, GitHub, etc.).
>
> To enable this feature:
> 1. Build the image with `WITH_OAUTH2_PROXY=true` (or use an image built with
>    this option).
> 2. Set `OAUTH2_PROXY=1` in your `docker-compose.yml` or `docker run` command.
> 3. Set `SECURE_CONNECTION=1` (default), as OAuth2 Proxy requires HTTPS.
>
> When enabled, the container checks for `/config/oauth2-proxy.cfg`. If missing,
> a default configuration for the GitHub identity provider is created.
>
> **Important:** The default configuration is incomplete. Edit
> `/config/oauth2-proxy.cfg` to configure your provider (client ID, client
> secret, etc.). Look for `CHANGE THIS` blocks.
>
> A local password database at `/config/oauth2-proxy-htpasswd` additionally
> allows local user login. Create entries with `htpasswd -B`. If
> `WEB_AUTHENTICATION_USERNAME` and `WEB_AUTHENTICATION_PASSWORD` are set on
> startup, that user is added automatically.
> </details>

## Local Image Build

> [!NOTE]
> Building this image requires Docker BuildKit (enabled by default in modern
> Docker). If needed, set `DOCKER_BUILDKIT=1`.

To build the image locally:
```bash
docker buildx build \
  --build-arg BASEIMAGE_VERSION=ubuntu-24.04-v4.11.2 \
  --build-arg GNUCASH_VERSION=5.14 \
  -t gnucash docker
```

To run the locally built image:
```bash
USER_ID=$(id -u) GROUP_ID=$(id -g) IMAGE=gnucash docker compose up -d
```
### Build Arguments

| Argument | Description | Default |
| :--- | :--- | :--- |
| `BASEIMAGE_VERSION` | Version of `docker-baseimage-gui` to start with. | unset - must be set on command line |
| `GNUCASH_VERSION` | Version of `gnucash` package to install. | unset - must be set on command line |
| `WITH_DOCS` | Set to `false` to build the image without GnuCash documentation (1). | `true` |
| `WITH_OAUTH2_PROXY` | Set to `false` to build the image without OAuth2 Proxy support (2). | `true` |
| `WITH_FINANCE_QUOTE` | Set to `false` to build the image without Finance::Quote support (3). | `true` |

1. At the time of writing (Feb. 2026), the documentation adds ~92 MB (~8%) to
   the uncompressed docker image size. The majority of the image size of ~1.1 GB
   is the `gnucash` package itself and its dependencies.
2. At the time of this writing (Feb. 2026), oauth2-proxy adds ~27 MB to the
   uncompressed docker image size.
3. On some Ubuntu versions, `gnucash` has a hard dependency on
   `libfinance-quote-perl`, so disabling `WITH_FINANCE_QUOTE` might not
   actually remove the package.
