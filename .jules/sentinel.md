## 2026-02-24 - [Argument Injection in local password setup]
**Vulnerability:** The script creating the oauth2-proxy htpasswd file uses `echo "${WEB_AUTHENTICATION_PASSWORD}" | htpasswd -B -i "${PASSWORD_FILE}" "${WEB_AUTHENTICATION_USERNAME}"`. This allows for a password starting with `-` to be incorrectly interpreted by `echo` (e.g. `-n`, `-e`). Additionally, `htpasswd` may incorrectly interpret a username starting with `-` as a flag, since this version doesn't support the `--` end of options delimiter, which could result in an argument injection vulnerability.
**Learning:** Shell commands that take user variables need special care to avoid variables starting with hyphens to be treated as command line arguments. Using `echo` on variables is unsafe for arbitrary strings.
**Prevention:** Use `printf '%s\n'` instead of `echo` when dealing with user variables like passwords. Ensure that usernames or user inputs that will be passed as arguments to commands that do not support `--` do not begin with `-`.
