## 2026-02-24 - [Argument Injection in local password setup]
**Vulnerability:** The script creating the oauth2-proxy htpasswd file uses `echo "${WEB_AUTHENTICATION_PASSWORD}" | htpasswd -B -i "${PASSWORD_FILE}" "${WEB_AUTHENTICATION_USERNAME}"`. This allows for a password starting with `-` to be incorrectly interpreted by `echo` (e.g. `-n`, `-e`). Additionally, `htpasswd` may incorrectly interpret a username starting with `-` as a flag, since this version doesn't support the `--` end of options delimiter, which could result in an argument injection vulnerability.
**Learning:** Shell commands that take user variables need special care to avoid variables starting with hyphens to be treated as command line arguments. Using `echo` on variables is unsafe for arbitrary strings.
**Prevention:** Use `printf '%s\n'` instead of `echo` when dealing with user variables like passwords. Ensure that usernames or user inputs that will be passed as arguments to commands that do not support `--` do not begin with `-`.

## 2026-10-31 - [Command Injection in environment variable script generation]
**Vulnerability:** The test script `tests/scripts/appready.sh` generates a shell script (`appenv.sh`) that exports environment variables of the running container so they can be sourced by test suites. It used `sed -e 's/^/export "/;s/$/"/'` to enclose the values in double quotes. This allowed arbitrary shell command execution (Command Injection) if a user-supplied environment variable value contained command substitutions like `$(...)` or `` `...` ``.
**Learning:** Sourcing a script containing `export VAR="VALUE"` evaluates the VALUE if it contains command substitutions, variables, or other shell expansions. Double quotes only protect against word splitting and globbing, not variable/command expansions.
**Prevention:** Use single quotes (`'`) instead of double quotes (`"`) when dynamically generating shell scripts that set environment variables from untrusted inputs. Single quotes disable all interpretation by the shell. Any existing single quotes in the value must be properly escaped by replacing them with `'\''`. (e.g. `sed -e "s/'/'\\\\''/g" -e "s/^/export '/;s/$/'/"`).

## 2026-02-01 - [OAuth2 Proxy Config Exposing Secrets]
**Vulnerability:** The OAuth2 Proxy configuration file (`/config/oauth2-proxy.cfg`) was created from a default template without restricting its file permissions. Because it contains sensitive data like `cookie_secret` and user-provided `client_secret` variables, storing it with world-readable permissions presents an information disclosure risk.
**Learning:** Default file creation (like via `cp`) inherits the default umask which is often too permissive (e.g. `644`) for sensitive configuration files.
**Prevention:** Always explicitly set restrictive permissions (e.g. `chmod 600`) and the correct owner (e.g. `chown app:app`) immediately after creating or copying configuration files that are expected to contain secrets, credentials, or API keys.
